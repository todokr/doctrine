# doctrine 開発者ガイド

doctrine の内部構造を、コードに手を入れる人向けに説明する。
プロダクトが何であるか（目的・原則・用語）は [`docs/overview.md`](../overview.md)、使い方は
[`README.md`](../../README.md) にあり、このガイドはそれらを読んだ前提で「どこに何があり、どう動くか」だけを書く。

## 読む順

| # | 章 | 読むとわかること |
| --- | --- | --- |
| 1 | [アーキテクチャ](01-architecture.md) | プロセスの構成、core の層、依存の向き、全体を貫く設計の約束 |
| 2 | [リポジトリとツールチェーン](02-repository-and-tooling.md) | ディレクトリの責務、版の固定、よく使うコマンド、CI、doctrine 自身の開発設定 |
| 3 | [ワークフローとタスク実行エンジン](03-workflow-engine.md) | ワークフロー定義、tick から Claude Code 起動までの流れ、状態機械、差し戻し・会話・上限待ち・マージ待ち・クラッシュ復帰 |
| 4 | [デーモン・永続化・RPC](04-daemon-and-persistence.md) | dctld の起動、ソケットとワイヤ形式、RPC とイベントの一覧、DB とマイグレーション、ディスク上の配置、dctl |
| 5 | [diff と Review Guide](05-review-guide.md) | diff の取り方、レビュー時点のツリー、hunk id、ガイドの生成・検証・表示、移動検出 |
| 6 | [Intake](06-intake.md) | Issue の取り込み、質問と仮定、PFD の検証とハッシュ、sub-issue、投入、マージの見張り、トラッカー |
| 7 | [デスクトップアプリ](07-app.md) | Tauri の中継、React の状態管理、画面とファイルと RPC の対応 |
| 8 | [テスト](08-testing.md) | テストの置き場と書き方、ヘルパー、統合テストの組み立て |
| 9 | [変更の進め方](09-contributing.md) | spec と plan、コードの規約、コミット、よくある変更の手順 |
| 10 | [既知の食い違いと未実装](10-known-gaps.md) | 既存ドキュメントとコードが食い違う箇所、設計にあって実装に無いもの |

初めて読むなら 1 → 2 → 3 → 4 の順に通し、あとは触る機能の章へ飛ぶ。
コア（`core/`）を触る人は 3・4 が土台になる。アプリ（`app/`）だけを触る人も、4 章の RPC とイベントの節は読んでおく。

## このガイドの約束

- **正はコードである。** 設計の経緯は `docs/superpowers/specs/` にあるが、spec は書かれた時点の判断で、
  後の変更で古くなっているものがある。食い違いは [10 章](10-known-gaps.md) にまとめた
- コードの箇所は `path:symbol`（例: `core/src/domain/engine.ts:runTask`）で指す。行番号は編集ですぐずれるので使わない
- 設計の「なぜ」は、ここでは要点だけを書き、詳しくは該当する spec へのリンクで示す
- 2026-09-26 時点（`f0a4c01`）のコードを元に書いている

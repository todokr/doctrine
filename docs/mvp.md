# doctrine MVP

[overview.md](./overview.md) で定めた全体像のうち、最初の段階で何を作り、何を確かめるかをまとめる。

## 段階

最初からインタラクティブなレビュー環境は作らない。

1. **MVP**: エージェントが構造化されたガイドを生成し、②のレビュー画面に表示する
2. **将来**: ガイドを1ステップずつ辿る Review Session（目的 → 中心の変更 → 設計判断 → 注意点 → 承認／差し戻し）として提供する

## 検証する仮説と成功指標

MVP で最初に確かめるのは次の問いである。

> **AIが生成した Review Guide によって、人がAIの変更を理解する時間と認知負荷は本当に下がるか？**

したがって、PRのマージ数を成功指標にしない。見るのは人の理解の確かさとコストであり、
筆頭は Reviewer Confidence である。

| 指標                        | 意味                             | 取り方                                        |
| ------------------------- | ------------------------------ | ------------------------------------------ |
| Reviewer Confidence       | 「この変更が何をしているか自分の言葉で説明できる」と感じるか | 自己申告                                       |
| Review Time               | レビュー開始から承認／差し戻しまでの時間           | `approval` ステップの待機開始から解決までを、デーモンが記録から導出できる |
| Misunderstanding / Rework | 「そもそも意図と違う変更だった」という齟齬の頻度       | 差し戻しの割合と差し戻しコメントから近似する                     |
| Review Preparation Time   | 開いてから変更の全体像を掴むまでの時間            | 自己申告                                       |

利用者は1人なので、比較はガイドの有無による自分自身の読み比べになる。
②（ガイド無し、diff と経緯だけ）が先に使えるようになるので、それが比較の基準線になる。

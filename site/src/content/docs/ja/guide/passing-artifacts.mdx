前段の `agent` ステップから後段へ計画やレビュー結果を渡すときは、前段に worktree の中のファイルへ書かせます。後段には、`{{ worktree.path }}` でパスを組み立てて読ませます。

```yaml
  - id: plan
    type: agent
    session: planner
    prompt: "計画を .doctrine-out/plan.md に書いてください"

  - id: review
    type: agent
    session: reviewer
    prompt: "{{ worktree.path }}/.doctrine-out/plan.md の内容をレビューしてください"
```

## `.doctrine-out/` は git の差分に混ざらない

`.doctrine-out/` という名前は慣例で、doctrine が強制するものではありません。プロンプトで指示する、ただの文字列です。ただし doctrine は、worktree を作るときにこの名前を `.git/info/exclude` へ自動で書き足します。`.git/info/exclude` はリポジトリで共通のファイルで、プロジェクトの `.gitignore` は書き換えません。これで次の 2 つが守られます。

- タスクが `completed` になると worktree は削除されますが、未コミットの変更が残っていると削除は拒否されます。この中間ファイルがその「未コミットの変更」と見なされて、削除を誤って拒まれることはありません
- レビュー画面の diff にも混ざりません。diff を取るときにも `.doctrine-out/` を除いているので、`.git/info/exclude` への書き足しとは別にも守られています

別の名前のディレクトリを使う場合は注意が必要です。自動で書き足されるのは `.doctrine-out/` だけなので、使う名前は自分で `.git/info/exclude` に書き足してください。

## 短い結果や人に見せたいファイルの渡し方

短い結果なら、ファイルを使わずに `{{ steps.<id>.last_stdout }}`（`agent` の最終応答）でも渡せます。書かせたファイルを人に見せたいときは、`approval` の `review.files` に並べます（[ワークフローを書く](../writing-workflows/)）。
